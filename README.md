# build-cp-testdata

面向算法竞赛命题与制题的数据生产 Skill。它将原题目录整理为一套可复现、可审核的工作流，覆盖中文题面重写、标准程序与暴力程序、数据校验与生成、错误程序攻击、部分分实测以及题解撰写。

## 主要能力

- 自动盘点原题目录，识别题面、`std`、题解、已有数据、错误程序和部分分程序。
- 在不改变数学问题与核心算法的前提下，将中英文原题统一重写为中文题面。
- 优先审计已有数据；数据合法且强度达标时直接复用，不强制重新生成。
- 生成或补全 `std.cpp`、`brute.cpp`、`gen.cpp`、`valid.cpp`、测试数据和标准答案。
- 按语义角色设计测试点，并使用正确解、部分分解和多类错误解检验数据强度。
- 支持独立测试点、子任务捆绑和混合计分，并按真实依赖关系实测得分。
- 对每个部分分给出实际可运行的代表程序和得分证据。
- 编写覆盖所有部分分、简洁且具有形式化论证的中文题解，并对题面、题解和报告执行独立的自然语言审校。
- 可在验收通过后生成离线 `polyhedron.zip`，保留已冻结的正式数据、计分单元和标准程序映射。
- 支持失败后从最近一个有效验收门继续重试，并输出最终发布审计结论。

## 使用方式

将本仓库目录放入 Codex 的 Skills 目录，然后向 Codex 提供：

1. 原题文件夹路径；
2. 输出目录；
3. 需要生成的数据组数；
4. 交付范围；
5. 独立、捆绑或混合计分方式，以及分组由你提供还是委托 Skill 设计；
6. 完全形式化、轻量背景或主题化题面风格；
7. 允许的改编范围、目标选手和题包格式。
8. 是否同时生成 `polyhedron.zip`；此项必须由用户明确选择。

原题文件夹必须包含 Markdown 题面与一份标准程序；题解、已有数据、错误程序、部分分程序和原部分分设置均可缺省。若标准程序实际缺失或无法验证，工作流会先补全并交叉验证标准程序。

除目录路径、数据组数和是否生成 Polyhedron ZIP 外，其他偏好均可回答“由你决定”。Skill 会记录这项授权及具体选择理由，不会静默套用默认值。时间、内存、输入输出和评测模式等技术信息会先从原题目录恢复，只有缺失或冲突时才继续询问。

主入口与完整规范见 [`SKILL.md`](SKILL.md)。输入合同示例见 [`assets/task.example.json`](assets/task.example.json)，可执行流水线示例见 [`assets/pipeline.example.json`](assets/pipeline.example.json)，编排脚本见 [`scripts/run_pipeline.py`](scripts/run_pipeline.py)。

## 可选 Polyhedron 输出

选择生成时，输出固定为题包根目录下的 `polyhedron.zip`。这是依据基准项目包络生成的离线格式与结构，不表示已在网站完成实际导入验证；Skill 不负责上传，用户需手动上传并检查目标平台结果。当前仅支持普通标准批处理题目以及 `tokens` / `exact` 输出比较。

启用后的显式打包命令和全流程命令分别为：

```text
python scripts/run_pipeline.py pipeline.json package
python scripts/run_pipeline.py pipeline.json all
```

`package` 会先完整执行构建、生成和评测；`all` 在已启用 Polyhedron 输出时自动打包。成功时报告记录 ZIP 的路径、哈希、成员与状态；失败或跳过时只记录状态，并明确旧 ZIP 不是本次成果。

## 环境

- 核心竞赛程序：C++14，建议使用 `-O2`。
- 流水线编排：Python 3。
- 文本文件统一使用 UTF-8 与 LF 行尾。

本 Skill 的题面与题解文本规范参考洛谷学术规范；两者共用同一套 Markdown、公式和渲染检查。人类可读文本另参考 [Humanizer-zh](https://github.com/op7418/Humanizer-zh) 中适合技术写作的编辑原则，只吸收直述、稳定术语、删减套话和避免模板化表达等内容，不采用反检测、刻意口语化或故意制造杂乱的做法。
